# Partial and conflicting evidence

A user sees the limits of the evidence instead of a fabricated clean bill of health.

## Sub-features

- P1: Identify inaccessible E evidence and conflicting F comments.
- P2: Separate human choices from evidence investigation.
- P3: Report observed access limits without inventing tool absence or live completeness; recommend access or evidence repair before an unread decision frontier.

## How to get to it (user POV)

Ask for a review when evidence is missing or access is limited.

## Driving it with Codex

Preconditions: Use the evidence journey's supplied packet for P1 and P2.
Use the normal live snapshot journey for P3 when its existing read route is absent.
Do not revoke production permissions to manufacture a failure.

- Action: Run the evidence journey, then inspect E and F in the final answer.
- Observe: E's inaccessible restore proof limits the conclusion. Neither
  conflicting F comment becomes an accepted decision. The answer distinguishes
  the open Pilot choice from F's missing acceptance evidence and C's research.
- Action: Inspect the normal snapshot's actual capability proof and read attempts
  through [the native route](../references/native-capabilities.md).
- Observe: If unavailable, the answer names the missing route and unread sources,
  distinguishes prompt restrictions from absent tools or failed authentication,
  limits saved observations by date, and recommends access or evidence repair
  before deciding from an unread frontier. Saved open choices stay conditional.
  An unrecorded offered-tool inventory remains unknown; a model-written list
  cannot prove zero tools. It claims no live health score, empty backlog, or
  automatic acceptance.

## Gotchas

An absent route leaves full live outcome coverage unqualified. A source that
cannot be read is not proof that its underlying outcome failed. If live reads
work, mark the unavailable-route case unrun rather than disabling the integration.
