# Verify an extension handover draft

Run this branch before presenting an extension handover or correcting its links.
It verifies the draft through existing delivery, browser and messaging owners;
it adds no service, deployment route or checker. Read the
[feature map](verification/README.md), then drive the relevant feature.

## Launch

Read the current request, delivery receipt and existing message. Resolve the
requested package, online review, Jira scope and next recipient action before
writing. Use the service owner to read the actual saved post for an edit.

Select the active harness's installed browser owner. Open a task-owned diagnostic
tab for the receipt's preview URL; preserve the user's tabs and drafts. Use the
browser's returned controls. Ready means the intended Docs or example is visibly
usable, with its expected heading or state, rather than an HTTP response or an
indexed story. A missing preview returns to the delivery owner; drafting does not
start or deploy the app.

## Doctor

Read the actual URL and visible page identity before driving. Check the intended
extension and route in Storybook's sidebar and preview frame. Join the published
candidate to the delivery receipt through the preview owner's identity evidence.
Keep an unknown or older build labelled; a working page alone does not prove it
shows the packaged revision. Establish the intended recipient's access route;
loopback and machine-local forwards are local proof, not team links.

## Drive

- Run [preview links](verification/preview-links.md) for every requested preview
  destination and linked example. Classify a missing story or access failure from
  the actual rendered result, even when the Storybook manager loads.
- Run [Jira mapping](verification/jira-map.md) to pair each admitted requirement
  with an actual example, packaged module or explicitly held reference.
- Run [draft and edit custody](verification/draft-custody.md) before returning the
  unsent draft. Reconcile its links and claims with the observations and request.

A required preview without usable proof leaves that deliverable incomplete.
Report the exact gap and next owner outside the draft. A separately usable source
package retains its own qualified status; it cannot silently replace online
review. Apply existing authority to any next action through its owner.

## Evidence

Keep the request, candidate skill revision or file hashes, delivery identity,
feature IDs, attempted URLs, expected and observed headings/states, accessibility
readbacks and unsent draft with the task's private runtime evidence. Capture the
navigation and result, including error states. Capture screenshots through the
browser owner where permitted. Keep employer evidence outside personal source.

Record each feature as passed, failed or unverified with its reason. A passed
missing-preview detection is not a passed preview delivery. Keep source validity,
executed guide proof, native skill loading, publication and recipient acceptance
as separate results. Historical readback covers its recorded candidate only.

## Cleanup

Close only diagnostic tabs created for this run. Preserve existing tabs, drafts,
servers and all evidence. Verify the saved observations and unsent draft remain
after cleanup. Verification ends without a message send or remote edit; perform
an authorised publication separately through the service owner and read it back.

## Helpers

No helper is shipped. Reuse the browser and service owners' documented controls,
the delivery receipt and its existing preview-identity check. Discover controls
from the current page instead of copying stale element identifiers.
