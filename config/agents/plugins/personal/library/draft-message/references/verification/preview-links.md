# Preview links

The recipient can open the claimed online review and reach the named state.

## Sub-features

- `preview-ready`: the intended Docs or state renders and its identity is bound.
- `preview-gap`: a missing story, access failure or wrong build stays incomplete.
- `preview-local`: a local-only URL retains its limited audience.

## How to get to it (user POV)

Open the draft's Catalog, Developer Guide or exact example link. For a correction,
start with the corresponding link or missing-link claim in the saved message.

## Driving it with the native browser

Preconditions: resolve the real preview URL, expected heading/state and declared
candidate from the delivery receipt. Use an owned diagnostic tab.

- **Open.** Navigate to that exact URL. Read Storybook's sidebar and the preview
  iframe, whose observed selector is `#storybook-preview-iframe`, when present.
  Wait for the expected heading or a visible terminal error before deciding.
- **Read.** Confirm the named extension and state in rendered content. A manager
  shell, loading indicator, successful response or `Couldn't find story` error
  does not qualify the example. Preserve the error or missing precondition.
- **Bind.** Read the delivery owner's published identity evidence. An unknown or
  mismatched revision remains unverified for the current handoff. Record a local
  URL's actual audience rather than treating it as a shared destination.
- **Draft.** Include each usable requested link beside the matching requirement
  or example. For a required missing preview, return a delivery-gap statement and
  next owner outside the copy. Preserve any separately qualified package status.

## Gotchas

A constructed story URL can load the manager while the story is absent. A local
forward can work for Nathan while colleagues cannot use it. Source-only examples
are appropriate to an accepted source-only handoff, not a substitute for a
requested online review. Unknown identity is a proof gap, not a guessed match.
