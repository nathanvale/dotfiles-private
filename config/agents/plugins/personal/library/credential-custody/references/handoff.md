# Hand off a credential operation

Record these nonsecret fields in the authorized handoff owner.

- Known host identity and target account.
- Harness and launch route, plus expected account home and any intentional
  harness-specific home or config directory.
- Credential owner, selected backend, and declared nonsecret mapping. Keep provider values and
  tokens inside custody.
- Exact authorized consumer operation and effect class.
- Source or installed payload revision and executable path.
- Metadata doctor result and time in Australia/Melbourne.
- Owner check result, including fallback source and original refusal when used.
- Provider or protected-account observation from the receiving process.
- Outstanding human action, unknown outcome, and next safe owner action.

Mark observations, user reports, assistant assertions, and inference separately.
Link to sanitized receipts in the runtime evidence owner. Promote readable
conclusions to the configured vault through Vault Steward. Do not copy raw
credential history into source or upload it to a service.

Use `planned`, `implemented`, `synthetic-tested`, `host-proved`, `installed`,
and `activated` only when the corresponding evidence exists. A GUI-domain
observation cannot be promoted to an unlocked Keychain or successful handoff.
