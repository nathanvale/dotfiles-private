# My Second Brain Playground Instructions

- Naming or planning: read [`CONTEXT.md`](CONTEXT.md). Use its canonical terms
  in source paths, packages, commands, schemas, skills, and Cast Roles. Invoke
  `domain-modeling` and update the glossary when a new domain term settles;
  update the root `CONTEXT-MAP.md` when a context boundary changes.
- Prototype promotion or implementation: read the relevant accepted Spec,
  Ticket, Bead, and [system direction](skills/playground-slice/references/system-direction.md).
  Trace each promoted behavior to named prototype evidence. Keep unsupported
  behavior experimental.
- Owner placement: keep executable plugin behavior here. Keep product intent in
  the Vault, delivery contracts in GitHub Issues, durable work state in Beads,
  live execution in Herdr, and readable views in Board Projections.
- Slice completion: use [`evaluate-slice`](skills/evaluate-slice/SKILL.md).
  Claim only the journey its evidence qualifies.
