# Vault agent routes

Choose one responsibility for the bounded work. Skills supply the workflow;
agent declarations supply the model and role boundary. Keep orchestration with
the current coordinator. These playground-owned roles do not require switching
the primary session to Sol Advisor.

## Trial roles

These model and effort settings are the requested trial baseline. Record useful
outcomes and ceremony before choosing a cheaper setting or claiming a routine
cost optimum. A successful run qualifies that run, not the routing policy.

| Work | Agent | Workflow |
| --- | --- | --- |
| Routine note updates, known-scope project packets, knowledge lookup | Vault Steward, Luna max | playground-slice routine route and the relevant family contract |
| Ambiguous evidence, synthesis, ownership or open planning | Vault Analyst, Terra high | Matching research, planning or context skill; caller names the responsibility |
| New Task creation, dependencies, claims, Gates, and closeout | The performing Cast Role, no delegated agent | beads-workflow native `bd` primitives under the Stage Manager's dispatch |
| An already-adopted legacy project's Agent Ledger Task transitions, evidence-based reconciliation and batch closeout | Ledger Steward, Terra high | tasks-first Ledger Steward branch; explicit Register, Task set and transition authority |
| Independent fidelity, retrieval, scope and ceremony judgment | Vault Evaluator, Sol high | evaluate-slice with frozen criteria and actual artifacts |

The plugin's `agents/msb-vault-*.toml` and `agents/msb-ledger-steward.toml` files own exact model pins and role
instructions. Codex user-scope copies live under `~/.codex/agents/`. Install from
the selected plugin payload and compare bytes before claiming the role is current.
These are Codex declarations; Claude role availability is not established by
installing the shared skills.

For native delegation use `msb_vault_steward`, `msb_vault_analyst`, or
`msb_vault_evaluator` with fresh context. For delegated Ledger tracking use
`msb_ledger_steward` and the [tracking handoff](tasks-first.md#handoff). Give the exact vault, accepted Task,
ordinary request, permitted paths, and stop boundary. Keep expected answers and
implementation conversation out of a baseline participant's prompt. The evaluator
receives criteria and actual evidence separately. Check actual model and effort
from runtime metadata; report unavailable or substituted roles explicitly.

Use Luna max for the requested bounded baseline trials. Escalate to Terra only when
observed ambiguity or judgment pressure earns it. Preserve the original result
and label the escalation; a stronger model's success does not qualify Luna.
Keep Sol Advisor as the existing optional code-orchestration owner when that
workflow is requested; its primary-session prerequisites remain its own.

## Whole cast mapping

| Cast responsibility | Initial execution owner |
| --- | --- |
| Creative Director | Nathan |
| Stage Manager | Current coordinating session |
| Task tracking | New work tracks in Beads through the performing Cast Role for a project that has adopted Beads; an already-adopted legacy project keeps its Task tracking in Agent Ledger, with Ledger Steward recording the coordinator-authorized subset |
| Project Steward; People, Organization, Product, Systems and Area Stewards | Vault Steward with the matching family workflow |
| Decision Secretary | Vault Steward records an already accepted decision through its adopted owner; never invent Ledger capability or acceptance |
| Researcher | Vault Analyst for bounded evidence and synthesis; existing research skill owns collection |
| Wayfinder | Vault Analyst for questions/options; current planning owner holds unresolved state |
| Teacher | Vault Analyst proposes lessons; owning skill/code receives authorized improvements |
| Idea Scout | Vault Analyst proposes ideas; coordinator routes and Nathan resolves consequential choices |
| Context Librarian | Vault Analyst using context-advisor for placement advice; content stays with its steward |
| Vault Caretaker | Vault Steward runs approved checks; fixes and maintenance remain separately scoped |
| Continuity Keeper | Existing checkpoint and vault-steward workflows; no new Git manager |
| Casting Director | Coordinator resolves installed capabilities through their existing supply-chain owner |
| Repository Engineer | Owning code repository and its implementation workflow |
| Relationship Reviewer | Deferred separate specialist with approved evidence scope and lens; no implicit Analyst authority |

Declare a further agent only when a distinct evidence boundary, authority,
workflow, or repeated failure earns it. Record baseline results by actual role,
model, effort, task and outcome. Earlier generic-model trials retain their original
identity and are not proof of these new role declarations.
